## 2. 与原教程不同的地方

| 项目 | 本包行为 | 原因 |
|---|---|---|
| 场景/机械臂/控制器 | 加载本机可信教程的场景类和辅助方法 | 不凭空重建另一套不匹配的 UR10e 配置 |
| 原脚本顶层 | 不执行原启动器、CLI 和 main | 一个进程只能由本入口初始化一次 SimulationApp |
| 模型输入 | RGB + 白名单本体状态；不发方块/目标真值 | 限制模型侧特权信息 |
| 控制目标 | 仍使用已知的配置坐标及教程偏移 | 没有实现三维视觉定位，明确承认这一边界 |
| 方块外观 | 设为红色 | 使任务指代在图像中明确 |
| 放置区域 | 增加无碰撞蓝色轮廓 | 原程序里的目标坐标未必有可见标记 |
| 相机 | Replicator 固定相机；零时间步采集 | 真正得到本次 RGB，避免 stale frame |
| 阶段选择 | baseline固定，shadow旁路，visual模型选择 | 统一执行和评分，隔离策略差异 |
| arm 最少步数 | 1 次执行更新 | 原源码统一60帧与lift最大50冲突，不适合直接作严格失败判据 |
| gripper 最少步数 | 60 次执行更新 | 保留夹爪稳定执行时间 |
| 最大阶段帧数 | 默认原值×4；可显式 `--frame-scale 1` | 首次集成预算，不冒充原教程精确复现 |
| RMPflow 重置 | 每次选择新的运动阶段均 reset | 模型可非线性跳转，不能只在固定几个阶段重置 |
| 夹爪目标保持 | 运动中继续写入当前夹爪目标 | 避免机械臂关节目标覆盖夹爪命令 |
| 到位/超时顺序 | 先查本次执行后的到位，再检查上限 | 防止最后一帧到位仍被记为超时 |
| 运动到位参考点 | 实测关节角经控制器模型 FK 得到同一工具点；物理手指位置单独保留 | 不把 `right_inner_finger` 与 `tool0` 目标混比；不宣称已完成模型/资产或抓取中心标定 |
| 阶段超时 | 终止本回合 | 不将“超过预算后进入下一步”当作动作成功 |
| release 结束后 | 自动retract，再固定静置120帧 | 两种策略使用一致的收尾与评分时机 |
| abort | 不执行收回，不推进额外物理 | 与中止语义一致；不是“成功结束” |
| 网络失败 | 记录错误，不重试/不静默回退 | 避免混合策略结果 |
| model mock | 显式标记；real模式拒绝 | 合成测试与真实模型实验不可混算 |
| 最终评分 | 几何位置、松开、超时和结束原因 | 教程的执行完成打印不是任务成功指标 |

## 3. 没有声称已经完成的能力

没有实际 GPU 端到端成功录像；没有验证任何具体显卡上的峰值显存或真实推理速度；没有机器人任务校准评估；没有证明视觉贡献；没有动态目标定位、完整重抓恢复、碰撞安全认证、真机控制、多用户并发、ROS 桥或 VLA 训练。

这些是明确的实验范围，不会用 mock、固定规则补完或事后挑选图片假装已经验证。
