# 完整操作手册：视觉决策模型控制 Isaac Sim 抓放

版本：v0.1.0 · 整理与源码核对日期：2026-10-05

## 0. 本手册的终点与限制

本手册的目标是启动以下**模拟机器人**实验：

> 相机拍到红色方块、夹爪和蓝色目标区域 → Intern-Decision 根据 RGB 与本体状态选择一个阶段 → cuMotion RMPflow 或夹爪驱动执行 → 下一阶段边界再拍照。

本包已经实现代码层面的全部连接，不要求读者自行补 `execute_grasp()`、`call_model()` 之类的占位函数。原交付环境没有 Isaac Sim；2026-10-06 后续在 L40 / Isaac Sim 6.0.1 完成固定场景 baseline 抓放和真实模型 shadow，但 shadow 后半段建议不合理，**尚未验证真实模型控制的 visual 成功**。CPU 测试不能替代 GPU 验证，shadow 的物理成功也不能算作模型控制成功。具体版本、实验目录和边界见 `TEST_REPORT.md`。

该版本固定物体和放置位置。模型收不到方块坐标；**执行器仍然知道配置中的抓取点和放置点**。所以这是“视觉选择高层技能 + 已知几何执行器”，不是“从相机独立完成未知位置的三维定位抓取”。它不会因加入了一张图片就自动获得空间定位能力。

## 1. 运行前需要什么

### 1.1 必要条件

| 项目 | 要求与验证方式 |
|---|---|
| 仿真主机 | 可正常运行 Isaac Sim 6.1.0 的 Linux + NVIDIA RTX 环境；本包文档按 Linux 独立发行包编写 |
| Isaac 安装 | 找得到 `python.sh` 和 `standalone_examples/tutorials/manipulation/tutorial_9_pick_place_cumotion.py` |
| 机器人/控制器 | 使用教程打包的 UR10e + Robotiq 2F-140 与内置 UR10 cuMotion 配置，不自带描述文件 |
| 模型环境 | 另建 Python 3.12 环境，完整下载 Intern-Decision-4B 官方快照 |
| 文件空间 | 安装包、模型和渲染缓存各自占空间；ZIP 不包含这些大文件，实际下载前检查目标磁盘 |
| 网络 | 首次下载权重、依赖及未缓存资产需要网络；模型推理默认走本机 HTTP，不需要 Jev API key |

这份代码不负责自动安装 Isaac、驱动或绕过许可确认。已安装的 Isaac 版本也不会因为设置了变量就变成 6.1.0。

官方 Tutorial 9 的目录、资产和内置描述配置见 [NVIDIA 6.1 Tutorial 9](https://docs.isaacsim.omniverse.nvidia.com/6.1.0/robot_setup_tutorials/tutorial_pickplace_example.html)。不应把 5.1 的 Lula `RMPFlow` 接口当成这里的 `RmpFlowController` 直接替换。

### 1.2 两个 Python 环境，不要混装

**终端 A：模型服务。**使用 Conda 环境中的 PyTorch、Transformers 和 Pillow。

**终端 B：Isaac。**使用 Isaac 发行包的 `./python.sh`，保留它自己的 Torch、Warp、Kit 与扩展依赖。

当前目标 GPU 云主机在每次启动 Isaac 前需要：

```bash
export OMNI_KIT_ALLOW_ROOT=1
export LD_LIBRARY_PATH=""
```

这两项作用于 Isaac 启动进程；不要在非 root 或其他主机上盲目沿用 root 许可。该云主机的 SSH 环境会把系统 `libpython3.12` 放在 Isaac 库前面，曾导致 Kit async_engine 启动崩溃。清空后 `python.sh` 使用自带 Python 3.12.13，已通过两轮真实 GPU baseline。模型环境仍独立，当前路径为 `/root/gpufree-data/envs/ivd-model`。

两边通过 PNG + JSON 的 HTTP 请求通信，像两个不同语言的服务通过 REST API 通信一样。这样不会为了模型更新 Transformers 时破坏 Isaac。

Mac 可以用于解压文档、SSH、浏览结果和运行 CPU 契约测试；本手册不声称能够在 Mac 上运行 NVIDIA RTX Isaac 仿真。

### 1.3 显卡分配

本包没有测得某一显卡的最低显存需求，不保证“单张 24 GB 一定够”。模型权重只是显存的一部分，视觉 token、推理临时张量、渲染器、资产和缓存也占用显存。

优先在现有主机上先测 Isaac 单独运行，再测模型单独运行，最后共存。有两张显卡时可以把模型和渲染分开；也可以把模型放在另一台 GPU 服务器，不需要换仿真框架。

## 5. 先拍一张真实 RGB

```bash
cd "$ISAAC_ROOT"
./python.sh "$LAB/run_isaac.py" \
  --isaac-root "$ISAAC_ROOT" \
  --mode capture \
  --headless \
  --run-dir "$LAB/runs/01_capture"
```

有桌面并希望观察 GUI 时去掉 `--headless`。该命令是独立应用入口，不应粘贴进 Isaac 的 Script Editor。

产物：

```text
runs/01_capture/
  manifest.json
  events.jsonl
  summary.json
  episodes.csv
  images/decision_000.png
```

`capture` 会创建场景、归零和预热机械臂后拍照；它并非完全不动机器人，但不会执行抓放阶段。

打开 `images/decision_000.png`，确认红色方块、末端夹爪和蓝色方形目标边框在画面中。目标边框由代码添加，**没有物理碰撞属性**。没有这个标记，只存在程序变量里的目标点无法被 RGB 模型看见。

目标框由 `visual_lab/sim.py::_decorate_scene()` 添加，位置来自配置 `target_position_m`，并非模型生成或原教程的官方视觉标记。边中心间距保持 12 cm；框线由 4 mm 加宽到 20 mm，默认相机的针孔估计约为 2–3 像素宽（旧值不到 1 像素）。颜色、相机、物体、目标与物理评分不变；实际可见性和模型收益必须检查新 GPU 图片，不能用投影计算代替。

相机默认 640×480，位置 `[1.8, -1.6, 1.5]`，朝向 `[0.65, 0.25, 0.2]`，焦距 18 mm，可以在配置里调整。该视角从负 Y 一侧俯看，扩大视野以容纳初始化时伸直的机械臂和夹爪；方块与目标仍保持原位置。几何取景测试不保证实际渲染中没有遮挡，必须检查生成的图片。初始化截图不是模型推理结果，也不是成功样例。

`capture` 只拍一张静态照片，不会让机械臂抓放。如果照片中红色方块看不到，先查看 `events.jsonl` 中 observation 的 `private_ground_truth.cube_world_position_m`：坐标接近 `[0.5, 0, 0.025]` 时，优先排查视角遮挡；坐标明显改变时，再排查初始化碰撞。这个坐标只用于诊断，不发送给模型。

### 相机同步的意义

本包使用 Replicator RGB annotator；拍照时暂停时间线，调用 `step(delta_time=0.0, wait_for_render=True)`。NVIDIA 文档明确说明零 `delta_time` 用于采集而不推进时间，等待渲染可避免返回前一帧数据。实现额外检查时间线、关节和方块在拍摄前后不变。[相机与采集来源](https://docs.isaacsim.omniverse.nvidia.com/6.1.0/replicator_tutorials/tutorial_replicator_getting_started.html)

拍照后执行下一阶段时，Kit 的 `timeline.play()` 请求要到下一次应用更新才生效。本包在同一次已计数的 `app.update()` 后检查播放状态，不额外增加等待帧；真正暂停或物理没有运行时仍会报错。旧版本若在 baseline 第一阶段立即报 `Timeline paused during an execution segment`，应更新项目，而不是放宽阶段超时或手动点击 Play。[Kit 时间线的逐帧状态生效规则](https://docs.omniverse.nvidia.com/kit/docs/omni.timeline/1.1.0/FRAME_INTEGRITY.html)

这个检查避免“图片是上一步、数值是下一步”的混合观测。第一帧可能需要加载资产和编译 shader；不要把首次加载时间当成每次模型决策延迟。

## 6. 运行不调用模型的固定基线

```bash
cd "$ISAAC_ROOT"
./python.sh "$LAB/run_isaac.py" \
  --isaac-root "$ISAAC_ROOT" \
  --mode baseline \
  --headless \
  --record-every 6 \
  --run-dir "$LAB/runs/02_baseline"
```

它执行：抓前 → 靠近 → 抓紧 → 抬起 → 搬运 → 放下 → 松开 → 自动收回 → 静置。

基线也使用同一场景、相机、执行器、阶段阈值和最终判据。模型 HTTP 服务此时可以完全不启动；`model_called` 应为 false。

**注意：这里的 baseline 是固定序列，不是完整的“独立反应式规则基线”。**后者需要额外实现状态分支和恢复规则，本包没有冒充已经实现。

生成报告：

```bash
python "$LAB/tools/make_report.py" "$LAB/runs/02_baseline"
```

打开 `report.html`，检查 `strict_success`、阶段误差、最终方块坐标。普通 Python 即可生成报告，不需要再次启动 Isaac。报告把模型可见状态和仅供评分的真实坐标分开显示。

基线失败时先停在此处。只增加模型无法修好场景碰撞、末端参考点、驱动器或 RMPflow 配置错误。

如果第一阶段运行到超时但机械臂完全不动，不要先增加 `frame_scale`。执行器每帧把机械臂和夹爪目标合并为一次关节目标写入，避免连续子集更新带来的目标覆盖风险；控制器没有返回关节位置指令时会直接报错，不再空跑到阶段超时。`events.jsonl` 的 `phase_end` 会记录：

- `controller_command_frames`：运动阶段成功提交的控制器指令帧数；夹爪阶段不调用控制器，值为 0。
- `last_joint_command`：最后一次合并提交的关节索引与目标角度，可与实测关节位置对照；指令存在不代表实际运动。
- `ee_world_position_start_m` / `ee_world_position_end_m`：阶段前后的末端实测位置。
- `controller_tool_frame`、`controller_tool_world_position_m` / `controller_tool_error_m`：控制器工具坐标系及由实测关节角计算的模型 FK 工具位置/误差；运动阶段使用这个误差判定到位，而不是把手指连杆与工具目标混比。
- `motion_position_tolerance_m`、`near_pose_stable_frames` / `required_near_pose_stable_frames`：本阶段运动位置阈值、近接触阶段连续达标帧数及要求；夹爪阶段仍按关节角和夹爪最少帧数判定。
- `joint_positions_start_rad` / `joint_positions_end_rad`、`max_joint_displacement_rad`：阶段前后的实测关节位置及最大净位移；净位移不是运动轨迹长度。

有指令但实测位置基本不变时，应排查指令应用和驱动；机械臂确实移动但末端误差不达标时，再检查参考点、控制目标和到位判据。这些数据只写诊断日志，不额外发送给模型。

**关节角已明显变化，但末端读数和画面仍保持初始姿态时，先检查物理位姿同步，不要断言机械臂没有收到指令。** CUDA 物理初始化会启用 Fabric 并抑制 USD 回写，而本项目 `GeomPrim` 位姿读取默认使用 USD。执行器现在在物理设备配置之后、场景加载之前禁用物理 Fabric 更新并恢复 USD 回写，统一末端、方块评分和画面的状态源。仍使用指定的 CUDA 物理设备，不切换到 CPU，也不额外推进时间；代价是逐帧回写的性能开销。

`events.jsonl` 的 `runtime.physics_pose_sync` 应包含 `pose_backend: "usd"`、`fabric_enabled: false`、`update_to_usd: true`、`suppress_readback: false`；设置未生效会在场景启动前报错。配置校验与 CPU 测试不能代替真实 GPU 抓放验收。

**控制目标和到位判据必须使用同一参考点。** 官方控制器通常瞄准模型 `tool0`，模型输入中的 `ee_world_position_m` 则一直是 USD 中 `right_inner_finger` 连杆的位置，不是 `tool0` 或抓取中心。执行器使用已加载 cuMotion 模型的 `Kinematics.position()`，按控制器关节顺序读取实际关节角，再通过实际机器人根姿态换到世界坐标。它不使用最后下发的目标角伪造到位，也不修改目标坐标或放宽 2 cm 容差。

`phase_end.convergence_position_source` 和 `runtime.motion_convergence_reference` 会标明该点来自 `controller_model_fk_from_measured_joints`；原 `ee_error_m` 仍保留为手指连杆到工具目标的诊断距离，不再是运动阶段的到位误差。**这改变了此前混用手指参考点的阶段判据，旧日志与新日志的阶段误差不能当成同一指标比较。模型 FK 到位不证明实际夹爪抓取中心已到位，也不证明 UR10 配置与 UR10e/夹爪资产已经标定匹配。** 方块真值、夹爪松开、无超时和完整结束的最终成功判据保持不变；baseline 和模型模式使用同一执行器。

### 抓起后搬运途中掉落

`grasp: reached` 只表示闭爪关节角达标，`completed` 只表示序列跑完。baseline 没有掉落检测或自动重抓，所以掉落后仍会执行 lower/release；最终方块位置不合格时仍判失败。不能把夹爪角度保持闭合当成持续夹住方块的证据。

先看 `images/decision_004.png`（闭爪后）和 `decision_005.png`（抬起后），以及搬运过程帧。若接触看起来只在指尖/方块上沿，并且 approach 以接近 2 cm 的模型工具残差结束，可先排查过早闭爪，而不是同时增加摩擦、驱动力或修改目标高度。

默认 `approach` 和 `lower` 现在使用 `near_pose_tolerance_m: 0.005`，并要求 `near_pose_stable_frames: 12` 个**连续执行更新**在阈值内（默认步长下约 0.2 秒）。越界即清零计数；在原阶段预算内达不到要求就超时，不额外补未计数的物理帧。其他运动仍用 `ee_tolerance_m: 0.02`，闭爪/张爪仍至少执行 60 帧。旧配置缺少新字段时，加载器会填入这两个明确默认值并记录到 manifest。

这是一轮针对浅抓风险的集成参数试验，不是 NVIDIA 推荐参数或已经验证的夹爪标定。**5 mm 是控制器模型工具误差，不是实际指尖/抓取中心的定位精度；连续到位也不证明接触或抓持可靠。** 未改变摩擦、驱动增益、控制目标、运输速度、物体碰撞或最终成功阈值；仍需真实 GPU 验证。


这是核对过公开推理脚本的固定提交，不是运行时任意变化的 `main`。下载完整快照，是为了让 `inference.py`、处理器、聊天模板、模型配置、权重和校准设置彼此匹配。[官方快照来源](https://huggingface.co/internlm/Intern-Decision-4B/commit/0e5e6aa7d6d750e2b1504ba11a8136cb58aeb3cd)

模型环境依赖按该快照公开要求锁定 Torch 2.9.1、Torchvision 0.24.1、Transformers 5.14.1。不要把手头其他环境中的 Torch 直接升级来凑版本；下载源没有这些包时，先排查镜像同步及源配置，不要默默改成旧 Transformers。

下载器生成 `DOWNLOAD_RECEIPT.json`，记录解析后的实际 revision 和关键文件哈希。中断时保留 `DOWNLOAD_IN_PROGRESS.json`；使用同一命令可以继续同一快照，不能把其他模型快照混入非空目录。

首次下载失败常见于网络、磁盘或镜像。若发生权限错误，先确认是否是下载源或认证问题；不能把下载不完整当成模型格式错误。

### 更小模型的选择

该桥接器原则上可以使用暴露同一 `DecisionEngine.predict` 契约的其他模型目录，但本包默认核对的是上述 4B 快照。更换 0.8B/2B 时，必须指定那个权重自己的 revision，并使用它自己的 `inference.py` 和温度配置；不要把 4B 的推理脚本复制过去后声称完成了兼容验证。

## 8. 启动本包的真实模型服务

仍在终端 A：

```bash
cd "$LAB"

# 阅读或审查 "$MODEL_DIR/inference.py" 后再授予显式执行许可。
python serve_model.py \
  --checkpoint "$MODEL_DIR" \
  --trust-model-code \
  --port 8765
```

`--trust-model-code` 表示允许执行已下载权重目录中的 Python 推理代码。这不是联网 API key，也不是绕过模型安全规则。没有这个显式选项，服务会拒绝加载。

默认 `device=cuda`、BF16、SDPA、`max_length=8192`，使用模型脚本自己的默认温度；不擅自覆盖或重新归一化它的输出。源文件 SHA256 会出现在健康检查与响应元信息中。

服务不会使用 `generate()` 生成 JSON，也不会访问 TypeSafe。它调用的是模型官方 `DecisionEngine.predict()`。

另开终端检查：

```bash
curl --fail http://127.0.0.1:8765/health
```

要求看到 `status: ok`、`bridge_schema: 1`、`is_mock: false`。健康成功只说明模型服务成功加载，不代表已用图片执行了一次推理。

该服务是**本包定义的桥接 API**：

```text
GET  /health
POST /v1/decisions
```

没有 `/docs`、`/v1/chat/completions`、`/v1/systemone`，也不支持任意数目/类型的问题。前面讨论过的 Intern-Decision 官方 demo server 不是这个进程，不能根据同名 `/v1/decisions` 就当成完全可互换。本包限定一张 PNG、一个 `next_stage` 题和八个固定选项，以减少接口歧义。

### 图片跨进程是如何传递的

Isaac 端把真实 RGB 编码为 PNG，再转成 Base64 文本装入 JSON：

```json
{
  "state": {"previous_action": "approach", "previous_result": "reached"},
  "images": [{"type": "image/png", "data": "这里是完整 PNG 的 Base64"}],
  "questions": {"next_stage": {"type": "choice", "instructions": "...", "criteria": {"...": "..."}}}
}
```

这个片段只是结构说明；真实字段和题目由 `visual_lab/protocol.py` 自动构造，不需要手工拼 JSON。

桥接器验证和解码 PNG，在**模型服务器自己**的临时目录创建图片，再调用官方引擎需要的 `images: [local_path]`，结束后删除临时文件。客户端不会把 `/mnt/...` 当作另一台机器上必然存在的共享路径。

### 判断不合理时的分离对照

动作英文描述是项目的 `visual_lab/protocol.py::CRITERIA` / `INSTRUCTIONS`，不是模型生成或官方任务提示词。当前描述给出可观察的适用条件和排除条件：已经抬起的方块不再做 pickup lift，已经闭合的手指不再做 grasp；同时解释 0/0.5 rad 的手指状态，强调手指连杆不是方块中心。它不根据上一动作硬编码下一动作、不删候选、不改模型返回，也不发送私有方块/目标坐标。

```bash

  --isaac-root "$ISAAC_ROOT" \

  --headless \
  --record-every 6 \
  --run-dir "$LAB/runs/04_visual"
```

这里真的由 `answers.next_stage.choice` 选择动作。不是拍照后仍暗中走固定序列，也不是视觉模型只负责写解释。

模型每次只选一个宏动作，阶段结束才再调用。推理期间物理暂停，因此模型延迟不会变成“机器人在等待时继续掉落”的未建模因素。**这是一种离线仿真实验协议，不是实时机器人部署方案。**

终止规则：

| 情况 | 结果 |
|---|---|
| 松开阶段到位 | 自动收回、静置后评分 |
| 选 `abort` | 本回合中止，不收回、不额外推进物理 |
| 任一阶段超时 | 本回合失败并终止，不继续假设成功 |
| 超过 16 次决策 | `decision_limit`，失败 |
| HTTP/模型异常 | `model_api_error` 或 `protocol_error`，不回退规则策略 |
| 关闭窗口/中断 | 记录运行错误或中断；不宣称成功 |

退出码：正常 `capture` 或严格成功返回 0；运行失败通常返回 2；参数/前置检查失败可能在启动 Isaac 前直接报错。调试时保留终端异常栈和对应 run 目录。

## 13. 时限与成功判据：不是照抄教程的“完成”打印

### 阶段完成

运动阶段：末端参考链接 `right_inner_finger` 到目标的距离 ≤ 0.02 m，至少经过 1 次执行更新。

夹爪阶段：`finger_joint` 到目标误差 ≤ 0.04 rad，并且至少经过 60 次更新。目标为打开 0、闭合 0.5。

“夹爪到位”只是执行目标达到，不等于真的夹住了方块。闭合后尚未抬起时，方块中心仍在地面高度是正常现象，不能据此立即判抓取失败。

### 超时

教程的八段上限是 `[250,150,100,50,150,100,100,100]`。源码中的统一最少 60 帧判定会与 50 帧的抬起上限冲突，本包没有直接复用这段状态转移。到位在最后一帧发生时，先判到位，再判超时。

默认 `frame_scale=4`，所以实际预算为 `[1000,600,400,200,600,400,400,400]`。这是为了首次集成而显式放宽的执行预算，不是 NVIDIA 原始指标，也不是已经调好的最佳参数。

需要原始帧数上限时：

```bash
# 同时对 baseline 和 visual 设置；不要只放宽其中一组。
--frame-scale 1
```

修改预算会改变实验协议，manifest 会记录。不要一边用原始预算跑基线，一边给模型更多时间后宣称公平比较。

### 物理完成与严格成功

默认方块边长 0.05 m，地面高度 0，所以静止方块中心参考高度为 0.025 m。放置目标配置 z=0.05 是技能目标构造的输入，**不是最终方块必须停在的中心高度**。

\[
d_{xy}=\sqrt{(x-0.5)^2+(y-0.5)^2}\leq0.05\;\text{m}
\]

\[
|z-0.025|\leq0.015\;\text{m}
\]

`physical_completion` 要求已执行到位的松开，而且最终位置符合上述几何条件。`strict_success` 进一步要求没有超时且以 `completed` 正常结束。

自动收回后，两组都再静置 120 个更新。判据没有额外要求“整个物体必须落在蓝框内”或“速度精确为零”；蓝框是视觉提示，评分用中心距离及高度。需要稳定速度判据时应另开版本，而不是悄悄修改统计口径。

## 14. 模型输入、隐藏信息与动作可用性

模型看到：当前一张 RGB、末端参考链接的世界位置、夹爪关节角、刚结束的动作及到位状态、固定任务说明和选项条件。

模型看不到：episode ID、决策编号、方块真值 XYZ、目标真值 XYZ、真值 `cube_held`、最终评分、标准答案。

执行器仍知道抓取点和放置点。`private_ground_truth` 只写入日志与评分路径，不进入发出的 request。查看 `requests/*.json` 可以直接核验这一点。

本版本没有独立 `open_for_retry` 技能。`release` 是结束操作，不是任意位置张开后继续重抓；`pre_grasp` 也不会自动打开夹爪。因此不能宣称本包已经实现了“掉落后总能重新抓取”。完整恢复需要额外动作、启动条件和位置估计，再重新定义协议与题目。

## 15. 常见故障按层排查

| 症状 | 先查什么 | 不应怎么处理 |

| 第一张图全黑或空 | 光源、相机朝向、RTX 驱动、资产/材质是否完成加载 | 用零数组替代图片继续算“视觉成功” |
| `Capture advanced physics` | 版本、时间线推进、Replicator 同步行为 | 先放大容差掩盖图片和状态不一致 |
| 阶段 `stage_timeout` | 报告的目标/误差曲线、末端参考点、tool_frame offset、预算、控制器 | 直接把超时记录改成到位 |
| 闭合夹爪超时 | 方块是否挡住了目标闭合量、夹爪驱动与几何；到位指标是否适合实际资产 | 把“发过 close 命令”当“抓住” |
| 模型 CUDA OOM | 单进程显存、是否另开了 Isaac、图像/上下文、GPU 分配 | 仅清空日志或无限重试 |
| `/health` 不是 bridge_schema=1 | 是否启动了本包 `serve_model.py`，端口是否被别的服务占用 | 把普通聊天服务当 typed decision 服务 |
| 422/`protocol_error` | PNG 是否完整、8 个标签、概率是否缺失/非法，官方引擎契约是否改变 | 缺少概率时自行补均匀分布 |
| 503 | 本包服务只允许一个并行推理；是否同时运行了 probe/shadow | 无限并发重试 |
| 180 秒 HTTP 超时 | 服务实际加载/推理状态、GPU、输入长度；必要时显式修改 config 超时 | 超时后悄悄交给基线 |
| 录像很短但实际等很久 | 录像只覆盖仿真时间，不覆盖模型等待 | 据此宣称实时推理 |
| 只有某个相机角度判断合理 | 模型视觉识别/域差异、遮挡、题目歧义 | 把单一视角结果当成鲁棒性结论 |

### 双 GPU 示例

模型环境中，只让 PyTorch 看到物理编号 1：

```bash
CUDA_VISIBLE_DEVICES=1 python "$LAB/serve_model.py" \
  --checkpoint "$MODEL_DIR" --trust-model-code
```

Isaac 使用自己的 Kit GPU 选择：

```bash
./python.sh "$LAB/run_isaac.py" --isaac-root "$ISAAC_ROOT" \
  --active-gpu 0 --mode visual --headless \
  --run-dir "$LAB/runs/05_visual_split_gpu"
```

不要假设 `CUDA_VISIBLE_DEVICES` 一定按相同规则控制 Vulkan/Kit 的 GPU 枚举。以 Isaac 启动日志、服务日志和 `nvidia-smi` 的实际进程为准。该示例不是对当前机器拥有两张 GPU 的断言。

### 远程模型的安全连接

模型服务默认只绑定 `127.0.0.1`。从**运行 Isaac 的主机**建立隧道：

```bash
ssh -N -L 8765:127.0.0.1:8765 MODEL_USER@MODEL_HOST
```

然后 Isaac 仍访问自己主机的 `http://127.0.0.1:8765/v1/decisions`。只在 Mac 上建隧道、而 Isaac 在另一台服务器上请求，不能让服务器自动使用 Mac 的本地端口。

需要认证时，在模型端和 Isaac 端设置同一个 `DECISION_API_TOKEN` 环境变量。本包的 token 不是 TypeSafe key。不要直接公开 HTTP 端口；本桥接器是单实验调试服务，不是生产级公网推理网关。

## 16. 本版的验收清单

一次真实实验完成应能提供：

1. `capture` 保存了可辨认的真实 Isaac RGB；
2. `baseline` 的物理轨迹与评分正确；
3. `probe` 的响应来自真实官方模型，不是 mock；
4. `shadow` 显示图像、建议与实际动作的对应关系；
5. `visual` 记录模型真正控制阶段的执行和结果。

接通只是第一层验收。模型可能连续选错或中止，这仍是有效的模型实验结果，不应让代码偷偷修正输出以制造成功视频。需要提高质量时，先基于保存的图像定位感知、决策、技能执行和评分中哪一层出了问题，再决定是否改提示、校准、动作集合或开展训练。
