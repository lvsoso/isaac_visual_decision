## 三个建议分别带来了什么

### 1. 中文：在三个表达背景下都改变了最后两步的选择

- 原始英文两种目标指认下都是 `pre_grasp → approach → grasp → lift → transport → transport → lift`，仍错在 `lower` / `release`。
- 中文原始数值在黄框下已经7/7；在蓝框下6/7，新增第一步错误：选择 `approach` 而不是 `pre_grasp`，但最后两步都改为正确的 `lower → release`。
- 中文空间描述在两色下均建议完整正确序列：`pre_grasp → approach → grasp → lift → transport → lower → release`。
- 六个中英条件配对的一致项差值为：蓝框 +1 / +1 / +3，黄框 +2 / +2 / +3，全部最后两步从0/2变2/2。这支持“**本场景中的这一版中文表达更合适**”，不证明模型是中文专用或任何中文翻译都会更好。

### 2. 明确蓝 / 黄色目标框：指认更清楚，但本轮没有新增正确动作

四个配对（两语言×两原图颜色）的一致项差值都为0；各七步的官方选择完全不变。它不是本轮修正最后两步的决定因素。

概率并非完全不变：第七步 `release` 概率增加0.72–2.49个百分点；第六步 `lower` 概率变化为−0.67至+2.45个百分点。因此不能说颜色说明没有任何作用，也不能据此认定必须删除颜色说明。

### 3. 厘米与相对位置描述：中文局部受益，英文反而退步

- 中文蓝框从6/7变7/7，纠正第一步；黄框保持7/7。最后两步在改写之前已经选对，空间描述没有新增最后两步正确项。
- 英文两色都从5/7变4/7，第二步新增错误：蓝框选 `grasp`，黄框选 `pre_grasp`。最后仍选 `transport → lift`。
- 中文空间描述虽然使蓝框七步全部一致，但 `lower` 概率下降1.27–3.02个百分点、`release` 概率下降2.20–6.65个百分点。不能把“更方便阅读”当成必然更有信心。

空间因素包含**单位、精度、自然语言格式、冗余几何表达简化**的整包变化；这一设计没有单独分离每一子项，也没有提供新的物体定位或绕障信息。
