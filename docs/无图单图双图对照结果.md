## 哪些动作改变了

参考顺序：`pre_grasp → approach → grasp → lift → transport → lower → release`。

| 条件 | 第一至七步：官方建议 |
|---|---|
| 无图，两色相同 | `pre_grasp → approach → approach → abort → abort → abort → lift` |
| 蓝框单图 | `pre_grasp → approach → grasp → lift → transport → lower → lift` |
| 黄框单图 | `pre_grasp → approach → grasp → lift → transport → lift → release` |
| 双图，两色相同 | `pre_grasp → approach → grasp → lift → transport → lower → release` |

- 无图仅前两步与参考一致；第三步仍选择接近而非闭爪，中间三步选 `abort`，最后选 `lift` 而非释放。**这些是逐个冻结状态的独立建议，不是一条真的执行过abort后又继续的机器人轨迹。**
- 加第一张图片后，两色均新增四个一致项，抓取、抬升、搬运判断恢复；蓝框修正下降，黄框修正释放。
- 加第二张图片再各新增一个一致项：蓝框纠正释放，黄框纠正下降。单图两组错误不同，不能只归因为文字或颜色，因为本轮没有隔离目标颜色的文字 / 像素各自效果。
- 双图14份输入与27批次中文明确颜色 / 空间描述**逐字节相同**，重新推理的官方choice和全部候选概率也**14/14完全相同**。没有直接复用旧答案。

## 能下什么结论，不能下什么结论

1. **仅支持原始输入删除的观察：**保留视觉要求却删图后，候选排序和参考一致项改变。不能分离缺少图像信息与提示要求不可履行的影响，不能用它判断合理纯文本提示下的能力或公平视觉收益。
2. **不支持：**模型完全理解了图像中的三维关系、纯视觉即可完成任务、任意场景双图一定更好，或已实现可靠自主抓放。本轮仍提供配置 / FK辅助，七个状态相关且已被观察过。
3. **无图abort不等于物理失败。** 提示要求核验方块是否被夹持，工具 / 手指信息明确不能证明夹持；缺图可能促成保守停止。但模型没有输出解释，不能声称已查明abort的内部原因。
4. **不是纯文本最佳提示评测。** 无图组保留了原文中的图像前提，没有改写成“仅依赖现有文字做最佳判断”；因此不能由2/7推断该模型纯文本推理普遍弱。若以后研究这个问题，应另设文案因素，不能在本批中事后补词混算。

本轮停止在诊断结果；不自动启动visual，不扩展独立新场景，也不把图片数量实验替代安全接管验证。
