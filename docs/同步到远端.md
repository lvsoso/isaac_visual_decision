# 把本机已提交的代码同步到 GPU 机器

## 在哪台机器操作？

**以下命令全部在 Mac 的本地项目目录执行，不是在 GPU 机器执行。**

GPU 机器访问 GitHub 慢时，不用一直等待 `git pull`。`tools/sync_remote.py` 把本机 `main` 的提交打成 Git bundle，经 SSH 传给 GPU 机器，再让远端 Git 快进更新。远端不需要访问 GitHub，也不需要安装本脚本或额外 Python 包。

本机和远端需要 Git、SSH/SCP、Python 3。远端目标必须是已经克隆好的项目根目录，且在 `main` 分支。此工具不初始化或覆盖已有目录。

## 第一次先检查

替换下面的用户名、主机、端口和目录，不要把密码加到命令中：

```bash
python3 tools/sync_remote.py \
  --host 用户名@主机 \
  --port SSH端口 \
  --remote-dir /远端/项目目录 \
  --check
```

`--check` 只检查两边的 Git 状态，不上传代码、不更新工作区。远端首次需要密码时，SSH 会在本地终端提示输入，输入内容不显示；脚本不读取、保存或打印密码。

脚本要求严格校验主机密钥。如果提示 `Host key verification failed`，先用普通 `ssh -p 端口 用户名@主机` 核对主机指纹并完成首次连接，不要关闭校验。没有可交互终端的自动任务需要预先配置公钥或已经建立的 SSH 连接。

## 以后怎么同步？

先测试、提交并推送本地修改，再运行相同命令，去掉 `--check` 即可：

```bash
git push origin main

python3 tools/sync_remote.py \
  --host 用户名@主机 \
  --port SSH端口 \
  --remote-dir /远端/项目目录
```

看到 `Synced and verified remote main: 提交哈希`，说明远端 `main` 已更新并核对了提交。两边已经是相同提交时不上传。SSH 连接会复用约 10 分钟，期间通常无需重复输入密码。

脚本只同步已提交的 Git 文件和历史：不会同步本地未提交文件、模型权重、虚拟环境或实验结果；不会修改远端 `origin` 地址；不会强推、reset、stash、删除运行目录或自动启动实验。忽略文件与新增跟踪文件发生路径冲突时，也会停止而不是覆盖。

## 提示有改动或历史不同怎么办？

- 本地不干净：先检查 `git status`，把应提交的改动验证、提交并推送后再同步。
- 远端不干净：去 GPU 机器运行 `git status`，确认哪些是你修改的文件或新增文件。先保存这些工作，不要直接丢弃。
- 远端不是 `main`，或提交历史不能快进：先检查分支与历史，让维护者处理，不使用强制覆盖。
- 传输中断：工作区不会被清空；再次运行即可。脚本会尝试清理自己创建的 Git 元数据内暂存目录，失败时会打印提示。

远端的 `origin/main` 缓存可能仍停在上次 GitHub fetch 的提交；直接同步不会伪造这个缓存。确认实际版本用 `git rev-parse HEAD`，不要仅根据“ahead of origin/main”判断同步失败。

同步成功后，再按操作手册运行实验。更新代码本身不等于 GPU 抓放已经验证成功。
