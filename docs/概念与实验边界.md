# 概念注释与实验边界

这份说明区分“已经实现了什么”和“一个成功视频仍然不能证明什么”。涉及本包实现的描述可以直接对照源码；上游 API 的来源列在 [来源与改动](来源与改动.md)。

## 1. 状态机不是只能从 1 走到 2

FSM（Finite State Machine，有限状态机）包含有限个状态、输入事件、转移条件和动作。它完全可以有分支、失败恢复和回退，不天然等于“只会按死顺序走”。

例如，一个人工设计的反应式 FSM 可以有：

```text
抓取 → 抬起验证 → 确认方块跟随 → 搬运
                   └→ 方块没跟随 → 张开 → 重新定位 → 再抓
```

本包的 `baseline` 只是固定八阶段序列，属于较简单的有限状态控制。它没有实现上图中的复杂分支。`shadow` 使用同样的执行序列，并旁路记录模型建议。

模型替换的是“选择下一宏动作”这一层，不是整个程序：循环、超时、权限、输入检查、动作执行、日志和最终评分仍由程序实现。

传统规则写成 `a = rule(o)`；决策模型写成 `a = argmax P(a|o)`。两者都可以依据环境反馈重新选择。公平比较不能把规则系统故意写得只会失败，然后据此证明模型更智能。

## 2. 世界状态、观测和本体感知

**世界状态（World State）**包括系统实际存在的信息，如方块真实 XYZ、速度和接触关系。

**观测（Observation）**是决策器在某一时刻能够获得的信息。它不一定包含整个世界状态。相机有遮挡，传感器有误差，单张图片可能看不出物体是否稳定夹持。

**本体感知（Proprioception）**是机器人对自身状态的测量，如关节角。末端位置通常还需要机器人运动学换算，而不是“相机看见了末端”。

**外部感知（Exteroception）**如相机对外部场景的观察。

本包使用：

\[
o_t=(I_t,p_t,h_t)
\]

其中 `I_t` 是 RGB，`p_t` 是末端/夹爪本体状态，`h_t` 是刚执行的动作及结果。它没有提供多帧视频和完整历史，因此遇到单图无法分辨的状态时不能期待必然判断正确。

## 3. 有视觉输入，不等于纯视觉控制

本包明确分成两条信息流：

```text
给模型：RGB + 本体状态 + 上一步结果
给技能执行器：配置中的抓取点、放置点和各阶段偏移
```

模型不知道 `cube_xyz`，不代表整个机器人系统不知道抓取点。**模型层没有真值坐标输入，控制层仍有已知几何先验。**日志把后一条标为：

```text
controller_target_source = configured_world_coordinates
end_to_end_visual_localization = false
```

因此适当的实验名称是：

> 视觉条件下的高层抓放技能选择，使用已知目标几何和传统运动控制器。

不适当的说法是：

> 模型仅凭 RGB 找到了任意方块的三维位置并自主抓取。

要达到后者，需要额外的视觉定位：例如 RGB-D + 分割 + 相机标定，或桌面平面约束下的标定映射，或真正输出动作的视觉机器人策略。单目像素 `(u,v)` 本身不唯一决定世界坐标 `(x,y,z)`，深度或几何约束不能凭空省略。

## 4. 宏动作与关节控制

宏动作（Macro Action / Skill）是一段持续执行的行为，例如 `transport`。决策器选中它之后，下层控制器会运行多个物理更新，直到到位或超时。

\[
a_k = \underset{a\in\mathcal A}{\arg\max}\;P_\theta(a\mid o_k)
\]

\[
u_t = C(x_t,\mathrm{target}(a_k))
\]

第一式选技能，第二式由控制器 `C` 在每个物理更新产生关节控制目标。`k` 是决策序号，`t` 是物理序号，一次 `k` 跨过许多个 `t`。

RMPflow 在这里负责跟踪笛卡尔目标。模型不生成关节角、速度、力矩，也不承诺每一条路径无碰撞。原教程的碰撞世界登记也有范围；操纵对象被排除在某些障碍查询之外，本包不是安全认证控制器。

VLA（Vision-Language-Action）是更广泛的视觉、语言与动作建模范畴，输出可以有不同表示，并不全部是连续浮点数组。这里真正需要区分的是**模型负责的层级**：本包只选择技能，底层动作由既定执行器生成，不是端到端训练的动作策略。

## 5. “末端到位”“夹爪闭合”“抓住物体”是三件事

本包读的是教程规定的 `right_inner_finger` 参考链接，不是自动识别出的夹爪几何中心。因此它和方块中心相差十几厘米时，不能不加分析就判“夹爪离方块太远”。控制参考点、工具坐标系和接触点不应混为一谈。

`finger_joint≈0.5` 只说明某个夹爪关节接近闭合目标。它可能夹住物体，也可能夹空气，或因物体阻挡未达到该角度。

**刚闭合但尚未抬起时，方块仍在地上是正常现象。**不能使用“方块高度没有增加”直接判定抓取失败。更合理的抓取证据需要抬起后的共同运动、多帧相对位置、接触信号或力反馈。

本包的 `lift` 可以用于第一次抬起验证；如果抬起之后图片显示物体仍在原处，模型应把它当成异常，而不是默认“执行过 grasp 就抓到了”。但本版动作集合并未提供完整的重抓流程，遇到无法继续的状态可以中止，不能虚构恢复已经成功。

## 6. 概率不是成功保证

Softmax 将选项分数转成概率形状的分布：

\[
p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
\]

这里 `z_i` 是模型对第 i 个合法候选项的分数，`T` 是温度。概率相加为 1 只是数学归一化，不代表已经在机器人任务上校准。

`P(grasp)=0.9` 不等于“整次抓放有 90% 成功率”，也不能单凭这个数批准危险动作。它受到候选项定义、模型训练分布和当前图像的影响。一个看不懂图像的模型也可能非常确定。

Intern-Decision 的公开推理接口中，Choice 的 `confidence` 使用选中项的概率；其他产品中同名字段可能不同，不能跨 API 直接等同。本包保留官方输出的 confidence 和全部候选项，不自行推测缺失字段，不把它当作安全证书。

若后续研究“低置信度时转人工”，需要先收集该机器人任务的标注与执行结果，再验证阈值的错误接受率/拒绝率。0.55、0.8 等数字不能因为看着合理就成为可靠性保证。

## 7. 影子模式在验证什么

Shadow Mode 是“模型旁听，但暂时不指挥”。好处是不会因为一个错误决策马上改变下一张图片，便于比较同一条基线轨迹上的模型意见。

但是它只观察基线到过的状态。真实模型控制后可能进入基线从没到过的状态，例如重复抬起或过早松开。这叫分布变化。影子模式表现良好是进入闭环的一个检查点，不是闭环表现的充分保证。

## 8. 真正的视觉贡献需要反事实实验

仅仅成功发送了 PNG，能证明“图像进入了接口”，不能证明模型确实使用了视觉证据。

后续可以在固定测试集上比较同一状态下：真实图像、空白/遮挡图像、错时图像、移除历史动作字段。观察输出是否响应视觉差异。但这必须与数据来源、评分方式一起明确冻结，不能在失败之后挑选有利例子。

本包暂不内置这些消融，也不内置移动方块的扰动。原因是当前技能目标固定；随意把方块挪走而不补视觉定位和重抓技能，模型即使做对高层判断，执行器仍可能到旧坐标抓空。那是在同时改变感知和动作可达性，不是干净的决策测试。

## 9. 仿真时间与现实时间

60 Hz 物理步长是 `1/60 s` 的模拟时间。模型调用期间暂停仿真，现实里经过的若干秒不会自动变成模拟时间。

因此：

\[
\text{录像时长}\neq\text{任务墙钟耗时}
\]

**墙钟时间（Wall-clock Time）**就是现实中的秒表时间。视频可以很流畅，而模型在两帧之间实际等了很久。真实机器人不会因为模型推理慢就暂停重力和碰撞，因此上线真机需要异步控制、延迟处理、在线观测、失效保护等另外一套工程。

## 10. 结果应怎样表述

适合：

> 在固定场景、已知技能目标、暂停式模型调用协议下，某次真实模型控制回合正常结束/中止/超时；附图像、概率、动作和评分。

不适合：

> CPU mock 测试成功，所以视觉机械臂已经跑通。
>
> 一个正常抓放成功，所以比规则控制器更可靠。
>
> 选项概率高，所以机器人执行是安全的。
>
> 加了相机且未输入方块坐标，所以整个系统完全没有特权信息。

本包优先保证证据链完整：输入是什么、模型返回什么、实际执行什么、执行结果如何。模型失败也是结果；不应通过静默回退、伪造概率或改写评分掩盖它。
