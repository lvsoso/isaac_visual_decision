## 执行步骤（串行；各步先测试再实现）

### 1. 双图接口（依赖：无）

背景：`visual_lab/protocol.py` 和 `server.py` 目前只接收一张 PNG；官方引擎支持多图。增加有界的一/双图 builder 和逐图解码、顺序/哈希元数据，保留默认单图调用与兼容哈希字段。无模型/API 密钥入日志。

验证：双图真实 localhost HTTP 替身往返、两个临时 PNG 内容/顺序、逐图坏数据拒绝、失败清理及单图回归。健康声明 max_images=2；保留每图3MiB、请求总5MiB限制。额外 processor 代理记录实际进入官方 processor 的有序 RGB 哈希及 image_grid_thw，拒绝截断请求并显式指定truncation=False，核对两图真正预处理；已核对固定官方编码器在前向之前检查完整输入长度并拒绝超长，不改张量、权重、原官方 inference.py。记录启动源码、processor配置、下载凭据哈希。CPU 不证明 GPU 模型接受双图。

### 2. 实验构造与成对 GPU 观测（依赖：1）

背景：`IsaacScene.capture()` 暂停且检查物理不推进；工具点来自实测关节 FK，不能用手指连杆充当工具点。为独立收集入口增加视觉颜色设置及指定相机采集能力，默认行为保持不变。

分别运行蓝/黄静态颜色的同一固定 baseline 轨迹；颜色在首次渲染之前写入，不进行运行中切色。七个动作执行前，同一渲染步更新两个 render product，再读取两个 annotator；同样三次零时间渲染步。每次核对全部关节、机器人根位姿、方块位姿、仿真时间不变。七阶段共用同一个实际 lower 技能模型工具目标，提取后恢复 _event，不触动控制器。位移=lower工具目标−实测模型工具位置，高度差=实测工具Z−lower目标Z；避免把配置 Z=0.05 当地面或物理抓取中心。实际执行 lower 后核对其目标与记录一致。

`tools/pair_factorial.py` 校验两次GPU物理成功、同源码/配置/相机、七阶段物理/工具/本体状态完全一致，随后核验14对目标ROI像素（红增且蓝减各≥8，至少20像素）。ROI是配置相机投影的近似边界，不是标定/视觉准确率标签，也不发模型。图片原字节复制，哈希不变；只有全部通过才生成配对目录。合成数据只能用于显式mock测试。旧INVALIDATED采集禁止重放。

ROI阈值仅为最低拒绝门槛，矩形内可含地板/夹爪，不能单独证明目标边缘颜色正确。执行者必须在正式重放前目视核查全部14对可见框边缘，确认蓝/黄真实显示，保存 `render_review.json`，绑定snapshots文件哈希、全部28图哈希和批准结论；启动包装命令先检查该凭据。没有批准不得运行56次正式推理。

验证：CPU 合成场景检查不进行live换色、所有配对物理状态完全一致、配置/路径/哈希/像素检查失败拒绝，目标/距离不依赖方块真值；GPU 检查两视图、两颜色确实渲染，两次物理 baseline 成功且无额外物理更新。

### 3. 八组离线真实模型重放（依赖：2）

背景：`DecisionClient` 只负责 HTTP；模型建议不能影响采集轨迹。独立重放工具读取不可变快照，新建输出目录，以固定种子交错八组/七阶段共56个请求。

先校验生产采集manifest（真实模式拒绝synthetic_fixture）、采集成功、七条记录、图片路径/哈希及双图服务能力；保存所有确切请求/响应、全部概率、延迟、源码/模型/配置/输入哈希。逐响应核对有序图片哈希、processor有序RGB哈希、图像grid数量、候选/argmax。模型输入以明确字段白名单重建，不能转发整个事件、配置或private_truth；更改方块真值不得改变B0/B1请求。全请求颜色中性；A只变图片，B只增goal_guidance，C只增第二图与对应视图描述；原手指状态在全部组相同。任何 API 失败立即终止，记录不完整状态，不跳过或补答案。

验证：CPU 替身完成56次配对重放及异常/旧目录保护；真实模型共56次成功（28单图、28双图），无模拟替身。只报告同一轨迹上的 baseline 一致项、最后两阶段、目标动作概率及四个背景组合下的配对差异；不把7阶段当独立试验，不报告泛化显著性或模型控制成功率。

### 4. 证据归档（依赖：3）

输出八组结果表、因素主效应的条件配对差异及完整原始概率；检查提示变化之外的配置和物理来源不变。观察高对比色效果必须查看真实渲染，不能以 USD RGB 数值替代实际对比度。

验证命令：`.venv-test/bin/python -m unittest discover -s tests -v`、Python 编译、相关函数行覆盖≥80%、`shasum -a 256 -c SHA256SUMS.txt`、`git diff --check`。CPU/GPU分开报告。

## 运维与恢复

- 每轮修改验证后提交并推送 origin/main，再通过现有 bundle 工具安全快进同步；不覆盖旧实验。
- GPU启动明确设置 `OMNI_KIT_ALLOW_ROOT=1`、`LD_LIBRARY_PATH=""`；模型留在独立环境。SSH密码仅由用户交互认证。
- 双图 bridge 需重启项目自己的 loopback 模型服务；先核对 PID、命令、健康、无请求/Isaac并行任务，保留旧日志并用新日志。无法确认进程归属就停止，不终止他人任务。
- 默认模式不切换到实验模式即恢复既有行为；失败保留部分记录，不能重用目录或强制推送。
- 本轮仅固定场景诊断。挑选组合后的独立新场景/模型接管验证未获本轮执行范围，不自动扩展。
